# dino-streamlit 계획

## 취지
사용자의 말: "https://pinko-eugene527.streamlit.app/ 이 사이트에 크롬 인터넷끊길 시 할 수 있는 게임 넣어서 내 깃허브 아이디로 사이트 연동해서 열어줘 그리고 그 게임은 유저가 튜닝한 버전이 있으면 그거 찾아서 그걸로 적용해줄수 잇는지 검토해주고"
이어서: "저 사이트가 아니라 사이트를 만든방식처럼 내 사이트를 만들어달라는 이야기야"

## 목표
`https://<이름>.streamlit.app/` 주소에서 크롬 공룡 게임을 할 수 있다. 코드는 공개 저장소 `mingilee97/dino-streamlit`에 있고, 사람들이 튜닝한 판 중 쓸 만한 것이 있으면 그 판을 쓴다.

## 하지 않을 것
- 게임을 직접 비슷하게 새로 만들기(원작이나 공개 튜닝판을 가져와 쓴다).
- 참고 사이트(pinko-eugene527)를 고치거나 그 저장소를 건드리기.
- 로그인·점수 서버·DB 같은 부가 기능.

## 단계
| 번호 | 할 일 | 완료 기준 | 담당 |
|---|---|---|---|
| 1 | 튜닝판 조사: 원작 추출본과 GitHub 포크·모드를 찾아 비교(무엇을 바꿨나, 라이선스, 마지막 갱신, 브라우저에서 바로 도는가). 참고 사이트가 어떤 구조인지도 확인 | `docs/보고서/2026-11-02_단계1.md`에 후보 3~5개 표(주소, 바뀐 점, 라이선스, 단일 HTML로 넣을 수 있는가)와 추천 1개가 있다 | 관리자 / Sonnet 조사 작업자 |
| 2 | 앱 만들기: 사용자가 고른 판으로 `app.py`, `requirements.txt`, 게임 파일, 라이선스·출처 표기 | `streamlit run app.py`로 로컬에서 띄운 화면에서 스페이스로 공룡이 뛰고 장애물에 부딪히면 게임 오버가 나온다(스크린샷을 보고서에 남김) | 관리자 / Sonnet 구현 작업자 |
| 3 | GitHub 공개 저장소 만들고 push, Streamlit Community Cloud에 배포 | `gh repo view mingilee97/dino-streamlit`가 public으로 나오고, `*.streamlit.app` 주소에서 게임이 뜨는 스크린샷이 보고서에 있다 | 관리자 / Sonnet 작업자(ego-browser로 사용자의 로그인 세션 사용) |

## 팀
총괄이 단계를 기획하기 전에 그 단계가 쓰는 줄을 읽고, 단계 지시서에 세션마다 건넬 문서와 스킬을 적는다.

| 역할 | 모델 · 수준 | 하는 일 |
|---|---|---|
| 총괄 | Opus 5.5 · max | 사용자와 기획한다. 단계 보고를 판정한다. |
| 관리자 | Opus 5.5 · high | 단계 하나를 맡는다. 일감을 나누고 결과를 확인하고 `진행.md`를 쓴다. |
| 작업자 | Sonnet 5.5 · high (조사·구현·배포) | 일감 하나에 새 작업자 하나. |

| 일감 | 건넬 문서 | 켤 스킬 | 까닭 |
|---|---|---|---|
| 튜닝판 조사 | `CLAUDE.md`, `docs/계획.md` 취지·하지 않을 것 | `caveman`, `ponytail:ponytail` | 원작을 새로 짜지 않는다는 선과 비교 기준을 알아야 한다 |
| 앱 구현 | `CLAUDE.md`, 단계1 보고서, 사용자가 고른 판 | `caveman`, `ponytail:ponytail`, `run` | 최소 구조로 만들고 실제로 띄워 확인한다 |
| 저장소·배포 | `CLAUDE.md`, 단계2 보고서 | `caveman`, `ponytail:ponytail`, `ego-browser` | share.streamlit.io는 사용자의 GitHub 로그인 세션이 필요하다 |
